# 玄枢移动端 P0 修复与验证报告

日期：2026-07-21

## 结论

本轮已完成产品审计中“数据真实性与主流程硬化”的第一批 P0 修复。无档案、示例、草稿和完整本地档案现在有明确边界；生辰、星盘、紫微和合盘不再静默借用示例资料或输出当前输入无法支持的精确结果。

当前版本可继续进行小范围本地与静态预览测试，但仍不等同于正式市场版本。下一阶段应先精简信息架构、压缩长报告和弱化合盘总分，再决定登录与正式后端方案。

## 本轮完成

### 1. 档案身份与路由守卫

- 无档案不再自动回退到完整示例档案。
- 报告、星盘、问答、合盘和生成路由统一增加档案能力守卫。
- 示例只能由用户主动选择，并全局持续显示“示例档案：小玄”。
- 旧版本中保存为“自己”的示例档案会在读取时迁移为“示例：小玄”。
- 草稿档案不会进入个人计算，而是显示补充资料入口。
- 新增 `empty / demo / draft / local` 档案类型和报告能力判断。

### 2. 创建档案与返回意图

- 三步创建流程现在每一步只显示当前字段。
- 只保存称呼后返回首页不会崩溃，也不会借用示例生日生成结果。
- 创建完成后保留安全的 `returnTo`，可以回到用户原本要查看的页面。
- 修复 `next=/m` 被错误降级到生辰报告的问题。
- 出生时辰未知时，地点说明不会再错误承诺可生成完整上升和宫位。

### 3. 生辰报告真实性

- 五行封面中心的日主、阴阳与五行改为读取当前报告证据。
- 标题、封面、专业四柱表和分享数据使用同一份标准化报告对象。
- 浏览器实测示例档案为“甲木 / 甲 / 阳木”，真实测试档案为“己土 / 己 / 阴土”，未再出现甲木标题配庚金圆环。

### 4. 星盘资料边界

- 未知时辰时不生成个人宫位、上升、天顶及其相关相位。
- 本命盘替代文本会明确标注“部分本命星盘，宫位待补充”。
- “今日行星”统一为“今日天象”，明确不使用个人宫位，也不是个人行运叠盘。
- 修复角度四舍五入产生 `21°60′` 的格式错误，正确进位为 `22°00′`。

### 5. 紫微真实十二宫

- 紫微首屏三组线索改为读取标准化计算结果，不再使用固定“最强/敏感/独特”文案。
- 十二宫组件改为展示 iztro 实际宫名、干支和主星。
- 修复视觉 CSS 遮住两宫、隐藏命身相关宫位的问题；当前页面实际展示完整 12 宫。
- 未知时辰时只显示补资料页，不用中午或随机时辰生成完整紫微。

### 6. 双人合盘

- 创建页保存双方档案快照，生成页可从持久化列表或快照恢复双方资料。
- 对方档案增加公历/农历和闰月数据字段。
- 移除不参与核心计算的 MBTI 输入。
- 进入生成前校验双方有效出生日期。
- 浏览器实测可从“测试草稿 × 合盘对象”完成创建、生成并进入长报告，双方资料均正确参与。

### 7. 运行与可访问性细节

- 修复 Next.js 平滑滚动配置警告。
- 首屏天体仪资源改为优先加载，清除 LCP 图片警告。
- 最新动态页与静态页浏览器控制台均无错误或警告。
