# 玄枢奇门引擎候选验证

## 结论

`qfdk/qimen` 可以作为第一候选排盘内核，但不能直接把整个仓库并入玄枢。建议只抽取排盘核心，通过 `QimenEngineAdapter` 隔离，并使用第二实现和人工标准盘做交叉验证。

## 已验证内容

- 2026-07-29 在隔离临时目录安装候选仓库依赖。
- `node --test` 共 26 项测试全部通过。
- 测试覆盖阴阳遁、局数、值符值使、地盘、天盘、九星、八门、八神、暗干、空亡、驿马和若干格局。
- 固定盘样例覆盖 2026 年春分、芒种、夏至后和秋分等时间点。

## 当前风险

1. 仓库是 Express 应用，不是面向第三方消费的稳定包。
2. `LICENSE` 和 README 标记 MIT，但 `package.json` 标记 ISC，正式使用前需要记录并澄清。
3. 完整依赖安装报告 1 个高风险和 1 个低风险漏洞；玄枢不应引入 Express/EJS 等无关应用依赖。
4. 测试数量有限，不能代表所有置闰、拆补、真太阳时和边界日期均正确。
5. 自动解读文案不进入玄枢，只考虑使用排盘结果。

## 上线闸门

- 建立 50 至 100 个标准盘夹具。
- 至少使用两个独立实现或人工排盘校验。
- 必须逐项核对局数、四柱、值符、值使、九宫、九星、八门、八神、空亡、马星和暗干。
- 所有差异必须记录起局规则，不能简单以多数表决决定正确结果。
- 通过许可证复核和依赖安全检查。
- 引擎只能通过适配器进入合参流程，UI 和报告不得直接依赖候选仓库对象结构。

## 玄枢集成边界

奇门只在明确的时间选择、行动选择和具体事件问题中启用。缺少问题时间或地点时不默认补值，也不生成伪造盘面。奇门输出先转换为统一证据，再与八字、紫微合并；冲突证据必须保留给用户查看。
