# 玄枢移动端产品流程修正记录

日期：2026-07-21

## 本轮目标

本轮不扩展新工具，集中修正用户实际使用时最明显的结构问题：入口重复、报告阅读缺少方向、合盘表达过度依赖分数、双方资料填写割裂，以及档案页操作不够清楚。

## 已修正

### 1. 首页、报告与工具分工

- 首页只保留每日状态、接着看和两个总入口，不再重复展示多组报告卡。
- 报告中心只收纳生辰、星座、完整星盘、紫微和流盘。
- 工具中心只收纳合盘与玄枢问答，未开放能力收进折叠路线图。
- 底部导航继续维持“首页 / 报告 / 工具 / 我的”，避免模块增加后继续扩充导航项。

### 2. 长报告阅读

- 生辰、星座、紫微、完整星盘和合盘报告增加资料范围说明。
- 明确区分“使用了什么资料”和“没有使用什么资料”，避免用户误认为所有结论都来自同一种算法。
- 增加吸顶章节导航、阅读进度和继续上次阅读。
- 报告顶部只展示当前已实现的体系入口，不再混入不可用标签。

### 3. 合盘流程与表达

- 创建流程拆成两步：先选双方和关系，再按需补充新档案资料。
- 本人和对方共用同一套出生资料字段，未知时辰不会被默认值替代。
- 结果页由“精确分数结论”改为关系区间和结构解释。
- 保留相对强弱图形，但不把关系简化成一个看似精确的数字。
- 补充资料来源、关系边界、章节导航和继续提问入口。

### 4. 档案管理

- 去除档案页重复报告入口。
- 删除档案、删除云端数据改为站内确认弹层，不再使用浏览器确认框。
- 示例档案的编辑入口改为创建真实档案，文案与动作保持一致。

### 5. 示例体验边界

- 示例档案可直接完成合盘，不再要求用户先补一份虚假的对方资料。
- 示例合盘可以完整查看和分享，但不会写入合盘历史。
- 示例问答只保留在当前页面，不写入本地问答记录。
- 页面统一提示“结果不进历史”，不再笼统声称所有记录都不保存。

### 6. 报告快读与专业依据

- 生辰、星座和紫微报告新增“快速看懂 / 专业依据”阅读切换。
- 默认先展示结论、场景和行动，术语、长文和专业盘面按需展开。
- 阅读进度达到 90% 后不再显示“继续上次阅读”，避免无效入口挤占首屏。
- 生辰真实报告不再运行时继承 `mockBaziReport`，全部字段由实际计算结果构建。

### 7. 导航与创建流程一致性

- 合盘、合盘历史和玄枢问答统一归属底部“工具”。
- 创建档案只在第三步完成后保存，删除容易误解的“先保存基础资料”操作。
- 合盘历史和结果统一使用定性关系区间，不再展示看似精确的关系分数。

## 新增通用组件

- `ReportDataScope`：报告资料范围与计算依据。
- `ReportReadingGuide`：章节导航、进度和续读。
- `ReportReadingModeSwitch`：快速阅读与专业依据切换。
- `ProfileFields`：本人档案与关系档案共用资料字段。
- `getRelationshipBand`：合盘结果与历史共用关系区间表达。

## 验证结果

- `npm run lint`：通过。
- `npm test`：12 个测试文件、55 项测试通过。
- `npm run build`：通过，50 条路由生成成功。
- `npm run build:mobile-static`：通过，25 个静态页面生成成功。
- `scripts/verify-p0-expansion.mjs`：星盘、报告中心、两种合盘模式和三档宽度回归通过。
- 375 x 812、390 x 844、430 x 932：核心页面无横向溢出。
- 浏览器控制台：0 条 warning / error。
- 合盘星盘模式与生辰模式：均完成选择双方、生成报告和结果存储验证。
- 报告续读：离开后返回可恢复阅读进度。
- `npm run qa:product-flow`：示例合盘、示例问答、工具导航、报告阅读模式和创建流程回归通过。

## 后续优先级

1. 用真实用户档案重新走一遍首次创建、回访、切换档案和删除档案。
2. 真机验证 iPhone Safari、微信 iOS、Android Chrome、微信 Android 的表单和固定导航。
3. 接真实云端同步前，补冲突合并和数据恢复流程。
4. 等现有闭环稳定后，再扩展塔罗、测试、灵数等新工具，避免再次稀释主路径。

## 当前边界

- 本轮没有重写生辰、星座、紫微或合盘算法。
- 本轮没有新增付费、社区、达人或假 AI 能力。
- 自动化与桌面浏览器预检不能代替四端真机验收。
